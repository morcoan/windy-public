# Windy v0.3.0 Release Report

> Public release report, published with owner approval on 30 August 2026.

## Outcome

Windy is now a terminal-hosted, static-analysis-only MCP substrate with a six-tool
agent surface and a demand-driven Evidence Query VM. The GUI, first-party agent
binary, and GUI/GPU dependency trees are absent. Investigations retain state on
the server and expose pre-bound action tickets, compact evidence deltas, and
immutable artifacts instead of requiring a weak model to assemble raw capability
arguments.

The release is version `0.3.0`. All mandatory local build and test commands
pass. Repository publication was authorized after local review.

## Architectural changes

- Six public MCP tools: `windy_status`, `investigation_start`,
  `investigation_step`, `evidence_read`, `change_commit`, and `target_close`.
- Typed intents compile into deterministic analysis operators. Common follow-up
  work uses an opaque `action_id`; the model does not repeat target IDs or bind
  capability arguments.
- Responses are proof-carrying evidence deltas with stable evidence IDs,
  explicit completeness, uncertainty, omissions, and repair choices.
- Analysis promotion is demand driven:
  `mapped -> catalog -> sketch -> function -> global -> deep`.
- Function sketches retain compact CFG, call, string/import, constant, memory,
  dependency, and motif facts. Full instruction/SSA/decompiler state is created
  only for active windows.
- The deep code index uses sorted eight-byte instruction metadata records rather
  than retained `iced_x86::Instruction` objects and per-instruction hash entries.
- Structural cache partitions are checksummed, ABI-keyed, atomically written,
  corruption recoverable, and bounded by a 5 GiB disk LRU. Agent annotations are
  journaled separately.
- Rename and comment changes use revision/idempotency checks and survive
  close/reopen without cloning structural analysis.
- Weak-caller repair is bounded and deterministic: a target path can recover
  one uniquely missing ASCII filename character, descriptive intent text is
  retained for analytical ranking, mutation bindings are selected by typed
  specificity, and continuation tickets perform a foreground wait rather than
  charging the model for a zero-work poll.
- Expensive orbit performance work moved out of the default test path; its normal
  test is a bounded smoke.

## Luna failure-driven evaluation

The private evaluator is a Python-standard-library SQLite harness under
`eval/microbench/`. It generates neutral stripped PE fixtures, isolates prompts
from source/gold data, uses deterministic scoring, and records calls, response
bytes, latency, failure stage, and answers. The existing large curator tree was
not loaded or changed.

| Metric | Frozen v0.2 paired | Final v0.3 paired |
|---|---:|---:|
| Cases | 12 | 12 |
| Passed | 3 (25.0%) | 12 (100%) |
| False support | 0 | 0 |
| Valid public calls | 82.81% | 100% |
| Median calls | 5.5 | 2 |
| Median tool bytes | 5,314 | 1,651 |
| p95 tool bytes | 9,101 | 4,443 |
| Median model-facing wall time | 46.32 s (timed supported-case replay) | 9.44 s |

The paired data remains in an unpublished local evaluation database: frozen
baseline run `v02-paired` and final run `v03-paired-final-recorded`. Quality improved by 75 percentage
points, median calls fell 63.6%, median tool output fell 68.9%, and p95 tool
output fell 51.2%. A replay of the baseline cases that had previously succeeded,
using the corrected first-call timer, measured 46.32 seconds median versus 9.44
seconds for final v0.3, a 4.9x reduction.

The first v0.3 sealed run remains unpublished and unchanged, including its
C-string selection miss. The failure-driven loop fixed the general causes—lossy intent binding,
ambiguous sketch evidence, zero-work polling, and edit-value parsing—then used
fresh Luna agents for the paired final run. No answer address was hard-coded.

The harness now starts wall timing at the first tool decision rather than batched
session initialization. Actual model token accounting is not exposed by the
subagent interface, so response bytes remain the visible-context proxy.

## Runtime measurements

Five cold and five warm repetitions used the release binary. Times are
milliseconds; RSS is the maximum working set observed by the benchmark harness.

| Target | Cold mapped p50 | Cold catalog p50 | Cold sketch p50 | Warm mapped p50 | Warm catalog p50 | Warm sketch p50 | Peak RSS |
|---|---:|---:|---:|---:|---:|---:|---:|
| `sample.exe` | 21 | 28 | 50 | 3 | 9 | 30 | 12.5 MiB |
| `complex.exe` | 21 | 27 | 51 | 3 | 9 | 28 | 12.5 MiB |
| Windy self binary (final) | 79 | 206 | 670 | 3 | 8 | 53 | 62.6 MiB |

The 53.9 MB self binary therefore returns a mapped handle below one second,
catalogs below three seconds, reopens below 500 ms, and remains far below the
1 GiB analysis-memory budget in this workload.

A valid minimal local MDMP containing a SystemInfo stream was parsed five times
in 12-19 ms. This is only a dump-parser smoke: the repository has no rich dump
fixture, so dump-module analysis and memory traversal were not performance
qualified in this run.

The self-binary deep index retained 10,740,446 compact records in 85,923,568
bytes. Five fresh-cache runs were 268, 277, 282, 295, and 279 ms (279 ms p50).
Against the earlier whole-image BEL observation of 202 seconds and 2.28 GB, this
is approximately 724 times faster and uses 96.2% less estimated index memory.
The comparison is architectural rather than an identical index-feature parity
claim.

## Research basis

The implementation follows demand-driven analysis rather than eager global
materialization, separates weak-model tool mechanics into deterministic server
operators, retrieves only task-relevant actions, and keeps observations short:

- Demand Interprocedural Dataflow Analysis:
  <https://dl.acm.org/doi/10.1145/222124.222146>
- Small LLMs Are Weak Tool Learners:
  <https://arxiv.org/abs/2401.07324>
- Re-Invoke:
  <https://aclanthology.org/2024.findings-emnlp.270/>
- Lost in the Middle:
  <https://aclanthology.org/2024.tacl-1.9/>

## Release qualifications

- The 9/12 quality gate (actual 12/12), zero-false-support gate, call-validity gate, output
  budgets, runtime gates, memory gate, deep-index gate, dependency gate, and
  default-test-time gate pass locally.
- The strict frozen-v0.2 versus v0.3 twelve-case paired experiment is recorded
  locally. The supported-answer timing gate uses a separate corrected-timer
  replay because the original v0.2 batch initialized every session up front.
- Absence of a rich dump fixture and unavailable model-token telemetry remain
  explicit limitations. The dump result is a parser smoke, and byte counts are
  used as the context proxy.
- Private benchmark databases, model trajectories, and `.zcode/` state remain
  excluded from repository publication.
