# Windy v0.2 architecture smoke

Measured on the baseline Windows host on 2026-08-29. These are implementation
smokes, not the required five-repetition release study.

| Gate | Result | Status |
|---|---:|---|
| Public tools | 12 | pass |
| `tools/list` HTTP payload | 7,421 bytes | pass (`<= 12 KiB`) |
| Default `function_inspect` HTTP payload | 1,665 bytes | pass (`<= 4 KiB`) |
| Duplicated structured JSON in text | none | pass |
| Release executable | 51.12 MiB | pass (36.3% below 80.2 MiB) |
| GUI/GPU crates in normal dependency tree | none | pass |
| Default library tests | 36.03 s | pass (`< 90 s`) |
| Self-binary open handle | 9 ms | pass (`< 1 s`) |
| Self-binary current catalog completion | 8,142 ms | **open** (`< 3 s` target) |
| Self-binary current peak RSS | 2,019.8 MiB | **open** (`<= 1 GiB` target) |

The self-binary result improved from the implementation-pass measurement of
9,608 ms / 2,164 MiB after removing the whole-image address hash table, but it
also demonstrates that the remaining eager `DecodedInstr` vector is still the
dominant architectural debt. Meeting the catalog and RSS gates requires the
next engine cut: mapped/catalog sessions must stop constructing a full
`Project`, and function windows must decode from mapped bytes into a bounded
LRU. This report deliberately does not label those gates complete.

The release smoke covers initialize, tool listing, MCP-only open, status poll,
semantic search, capability execution, function inspection, native
decompilation, close, and endpoint diagnostics. The standalone local
agent-bench v2 smoke ran two stripped P0 locate tasks in 1,656 ms and honestly
abstained on both; it demonstrates transport/tooling wiring, not model-quality
acceptance.
